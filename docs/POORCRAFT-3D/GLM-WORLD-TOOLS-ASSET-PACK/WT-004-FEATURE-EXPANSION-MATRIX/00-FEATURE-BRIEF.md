# Feature Brief

POORCRAFT 3D is not a small survival prototype. The target is a wide sandbox
RPG with construction, exploration, NPC life, faction strategy, industry,
magic, multiplayer, and moddability. WT-004 creates a map so future GLM/Z-code
passes can add breadth without losing proof discipline.

## Rules

- Ship vertical slices, not disconnected systems.
- Every feature must have a player-facing reason to exist.
- Every feature must expose state to the observatory from WT-003.
- Every visual feature must have screenshot proof.
- Every asset feature must obey WT-002 semantic asset laws.
- Every world feature must respect deterministic seeds from WT-001.
- Every broad system must be represented in machine-readable JSON so tools can
  plan, test, and track it.

## Feature Definition

A feature is accepted only when code, data, UI, asset needs, tests, screenshots,
and observatory evidence agree. A design note is not a feature.
