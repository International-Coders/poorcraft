# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-004
- Title: Profiler counters, frame-time capture, memory counters, and a baseline hardware/profile record
- Stage/gate: P3D-000 (project boundary and truth)
- Owner/model: owner directive "MAKE ALL described in the folder"; z.ai GLM session
- Date: 2026-09-04

## Goal

The engine can measure itself from birth: named counters for the work the
performance principles call out (mesh, fluid, path, entity, network, save),
frame-time capture with p50/p95, memory counters, and a machine-readable
baseline profile record written once and diffed by tests.

## Current truth

- `pc3d_core` has the deterministic spine (clock/command/journal/seed/
  replay), 24 tests green. No runtime loop exists yet (P3D-005), so all
  measurement is library-level: counters a future host ticks, plus a real
  capture utility proven on synthetic work in tests.

## Scope

### Must change

- `pc3d_core::profile` — `Counters`: named u64 counters via a fixed
  `CounterId` enum (the performance-principles list: mesh work, fluid work,
  path requests, entity ticks, network bytes, save bytes, patch rebuilds,
  journal events) with `inc`, `add`, `snapshot` (deterministic order).
- `FrameTimes`: push raw frame durations (f32 ms), `percentile(p)`
  (nearest-rank), `p50/p95/min/max`, and a `digest` for regression tests.
- `MemoryCounters`: allocated_bytes/freed_bytes/allocations counters with
  `net_bytes` — fed by explicit calls now; a global allocator hook is a
  later, opt-in change (not this task).
- `BaselineRecord`: one machine-readable record (struct + display line)
  naming the profile (host arch, OS, profile name, P3D format epoch) plus
  the counters/frame stats captured; written by the binary via
  `poorcraft3d --baseline` to stdout as JSON; a test pins that the record
  serializes deterministically (same inputs → same bytes).
- Binary: `--baseline` flag.

### Explicit non-goals

- No global allocator replacement, no threaded aggregation, no UI overlay
  (terrain debug overlay is P3D-207), no GPU timings (no renderer yet).
- No performance CLAIMS — this task builds the measuring stick; budgets
  arrive with the subsystems they measure (P3D-201+).

## Contracts and invariants

- deterministic behavior: snapshots iterate CounterIds in enum order (never
  hashmap order); percentile is nearest-rank on the sorted sample.
- authority/ownership: `pc3d_core::profile` owns the counter vocabulary;
  subsystems increment, never redefine.
- save/load behavior: n/a.
- network behavior: n/a.
- performance budget: counters are single u64 adds (no locks in this
  single-threaded core); FrameTimes is a fixed-cap ring.
- player-visible result: `poorcraft3d --baseline` prints the profile
  record — the first evidence the engine can see itself.

## Verification

- unit/integration tests: counter inc/add/snapshot order; percentile math
  on a known sample; memory net arithmetic; baseline determinism (two
  builds of the same record → identical JSON bytes).
- persistence/replay tests: digest stability of FrameTimes under identical
  samples.
- visual proof scene: n/a.
- smoke or multiplayer test: `poorcraft3d --baseline` exits 0.
- profiling/counter evidence: this task IS the evidence machinery; the
  DEVLOG records the first baseline numbers from the synthetic test workload.

## Done when
