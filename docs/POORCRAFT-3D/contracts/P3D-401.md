## Goal

The first PERSON moves through the POORCRAFT 3D world: a deterministic
capsule-style controller walking on `final_solid` terrain (step-up ≤ 1 m,
walls block), swimming in Water cells (buoyancy, slower movement, swim-up
with jump), and a safe spawn that always lands on walkable land above sea
level — all integrated on the engine's fixed clock.

## Current truth

- `final_solid` answers terrain solidity per cell (P3D-202); Water cells
  are non-solid; the FixedClock (P3D-003) provides deterministic ticks;
  hydro provides river regions (P3D-301) for spawn placement.
- No movement code exists.

## Scope

### Must change

- `pc3d_world::player`:
  - `Player { pos_m: [f32; 3] (feet position, meters), vel, on_ground,
    swimming }`; body AABB 0.6 wide, 1.8 tall.
  - `MoveInput { move_x, move_z: f32 (world-space, magnitudes 0..1),
    jump: bool }`.
  - `Player::spawn_safe(gen, seed) -> Player`: deterministic scan — a
    river region with land, then spiral out for a column whose surface
    cell and the 2 cells above are passable (air/swim) with a solid
    floor; spawn 1 m above the floor.
  - `step(gen, input)`: one 60 Hz tick — gravity (fall ~18 m/s²,
    terminal ~40 m/s), horizontal acceleration toward input velocity
    (walk 4.3 m/s, swim 2.2 m/s), axis-separated collision resolution
    (x, then z, then y), STEP-UP: a horizontal move blocked at knee
    height but free at knee+1 m steps up onto it, swimming: buoyancy
    (gravity −60%, terminal sink ~2 m/s) and jump swims upward,
    on_ground tracking.
- Tests: spawn safety across seeds (on land above sea level, air above,
  solid below); flat-ground walk stays level (no sink/climb); 1 m step
  climbs; 2 m wall blocks; gravity falls; water buoyancy (sinks slowly,
  never below the water column floor); determinism (same input stream →
  identical positions); swim speed < walk speed.

### Explicit non-goals

- No camera/mouse/UI (P3D-402+ and the renderer stage), no jumping
  heights beyond a fixed 1.25 m impulse, no sprinting, no entities.

## Contracts and invariants

- deterministic behavior: fixed dt (SIM_DT), fixed operation order per
  tick; same inputs → identical trajectories.
- authority/ownership: `pc3d_world::player` owns the controller; the
  host ticks it.
- save/load behavior: position/velocity are plain fields (persist with
  the host later).
- network behavior: n/a.
- performance budget: O(1) collision samples per axis move.
- player-visible result: the player walks, climbs steps, swims, and
  always spawns somewhere sane.
