## Goal

Every river region carries a versioned FLOW RECORD — direction, slope
(fixed-point), discharge, capacity, revision — derived deterministically
from the river graph; neighboring regions exchange BOUNDARY PORTS (an
exit on one side is an entry on the other, at the same world position);
and flow tables persist through the P3D-102 framing law.

## Current truth

- `pc3d_world::hydro::RiverGraph` (P3D-301) provides flow directions and
  discharge per region. No flow records, ports, or persistence exist.

## Scope

### Must change

- `pc3d_world::flow`:
  - `FlowRecord { region, direction: u8 (0..8 compass, 8 = sink),
    slope_per_mille: i32, discharge: u64, capacity: u64, revision: u64 }`.
    Slope = (elev_here − elev_downstream) × 1000 / edge distance mm
    (fixed-point, no floats persisted). Capacity = slope-scaled channel
    capacity (deterministic v1: discharge × (1 + slope/50)).
  - `FlowTable::from_graph(graph)`: one record per region with a
    downstream; `revision` starts at 1; `bump_revision()` for rebuilds.
  - `ports_for(region) -> Vec<Port>`: for each river neighbor, a port at
    the shared border midpoint with direction (out toward downstream,
    in from upstream) and discharge. PORT MATCHING LAW: region A's exit
    toward B and region B's entry from A share the identical world
    position and discharge.
- `pc3d_save::flow_store`: `save_flow_table/load_flow_table` through the
  header law (fixed-width records).
- Tests: derivation determinism; direction consistency with the
  downstream map (8-compass); slope sign (never negative toward
  downstream); port matching across a shared border; persistence
  round-trip + foreign/wrong-version refusal; revision bump.

  refusal matrix applies.
- network behavior: n/a.
- performance budget: O(regions) table build.
