## Goal

Player-built blocks exist as explicit construction data — the blueprint's
terrain layer 3: a built cell wins over the natural base wherever they
overlap, carries an owner, is removable only through its own op path, and
a natural terrain dig/fill can NEVER destroy a built block. The world
answer query gains the construction overlay so mesh, collision, and
gameplay all see built blocks through the same single answer.

## Scope

### Must change

- `pc3d_world::build` (pure model):
  - `BuildBlock { material: CellMaterial, owner: u64 }` and
    `Construction { coord, cells: Vec<Option<BuildBlock>> }` — explicit
    per-patch construction data (16³ slots, None = no build).
  - `BuildOp { id, tick, kind: Place|RemoveBuild, cell: CellCoord,
    material, owner }` with fixed-width 48-byte encode/decode (cell-
    precise — construction is not brushed).
  - `Construction::place/remove` with OWNERSHIP: a RemoveBuild by owner X
    on a block owned by Y is rejected; Place replaces only Air/no-build.
  - `Overlay` trait/helpers: `effective(gen, construction_opt, wx, wy, wz)
    -> SolidAnswer` — construction wins over the natural base wherever a
    built cell exists; otherwise the P3D-202 natural answer applies.
  - The PRIORITY LAW as a function: natural dig/fill (`edit::apply_edit`)
    must skip cells that carry construction (a built-cell registry per
    patch is passed in and honored), so terrain reshaping can never
    destroy a build.
- `pc3d_save::build_journal`: `save_build_journal/load_build_journal`
  through the header law (`edits/b<x>_<y>_<z>.build`), plus
  save/load of construction snapshots (`s<x>_<y>_<z>.bsnap`).
- Tests: place/remove + ownership rejection; place rejects replacing an
  existing build; construction wins in `effective` (built block over dug
  ground, built block over water); terrain dig/fill skips built cells
  (the machine-protection law); build-journal IO round-trip + foreign/
  wrong-version refusal; byte determinism; the P3D-202 natural answer is
  unchanged when no construction exists.

### Explicit non-goals

- No meshes/visuals for builds, no doors/machines semantics (those come
  with content stages), no structural integrity, no network replication.

## Contracts and invariants

- deterministic behavior: placement/removal pure; construction cells
  ordered by cell index; encodings fixed-width LE.
- authority/ownership: every built cell carries exactly one owner; only
  the owning authority removes it (model level).
- save/load behavior: construction journals/snapshots persist under
  `edits/` through the P3D-002 law; refusal matrix applies unchanged.
- network behavior: n/a.
- performance budget: O(1) place/remove; effective answer O(1) over
  natural.
- player-visible result: build a block on a hillside, dig around it —
  the block survives; only you can remove it.

## Required design check

- Which player story does this improve? The builder: what I build is
  MINE, persists, and cannot be eaten by the terrain.
- Which two game layers does it connect? Natural terrain (layers 1–2) ↔
  construction (layer 3) under one world-answer function.
- What must a player be able to see or do when it works? Place a block,
  dig the hill under it, reload — the block remains, owned, intact.
- What user-approved decision does it depend on? D-004 (buildable natural
  terrain) and the blueprint's three-layer terrain separation.
