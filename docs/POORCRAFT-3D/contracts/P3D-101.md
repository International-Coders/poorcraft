## Goal

The world substrate's spatial language exists as pure, tested code: stable
64-bit world positions in meters, the region/patch/cell hierarchy from the
terrain blueprint (15-TERRAIN-TECHNICAL-BLUEPRINT.md), correct floor-division
mapping across negative coordinates, bounds algebra, and bounded spatial
queries — all with the proposed scales (1 m cell, 16 m patch, 256 m region)
declared as constants in exactly one module so a pending owner decision
(P-001/P-002) re-scales the world in one place.

## Scope

### Must change

- New crate `poorcraft3d/crates/pc3d_world` (workspace member; zero
  dependencies — pure geometry substrate).
- `scales` module: MM_PER_METER, CELL, PATCH, REGION sizes with compile-time
  coherence checks (patch == cells × cell, region == patches × patch).
- `coords` module: `WorldPos` (i64 millimeters, the 64-bit stable identity),
  `CellCoord` (i32, floor-mapped), `PatchCoord` (i32×3), `RegionCoord`
  (i32×2, horizontal), `LocalPos` (millimeters within a patch), all
  conversions via `div_euclid`-correct helpers.
- `bounds` module: `WorldBounds` (min/max inclusive), contains/intersects/
  union, cell-count volume; guards against overflow on huge spans.
- `query` module: `patches_touching(bounds)` and `regions_touching(bounds)`
  with a hard iteration cap (`MAX_QUERY_PATCHES`) so a planet-sized bound
  cannot hang a caller; `patch_origin`/`region_origin`/footprint helpers.
- Tests: round-trips through all sign combinations; boundary identities
  (a cell knows its patch, a patch its region, origins invert); blueprint
  values pinned (1/16/256 m); query boundedness; overflow guards.

### Explicit non-goals

- No generation (P3D-103), no patch store/save (P3D-102), no interest rings
  (P3D-105), no density/material evaluation (P3D-202), no meshing.
- No pc3d_core dependency yet — the substrate stays pure; header/identity
  integration arrives with the save path.

## Contracts and invariants

- deterministic behavior: all pure integer math; `div_euclid`/`rem_euclid`
  so negative coordinates floor correctly (a cell at x = -0.5 m is cell -1).
- authority/ownership: `pc3d_world` owns the spatial vocabulary; other
  crates convert through it, never hand-roll offsets.
- save/load behavior: n/a; coordinates are chosen so serialization is
  trivially fixed-width later.
- network behavior: n/a.
- performance budget: every query O(patches touched) with a hard cap; all
  conversions O(1) integer ops.
- player-visible result: none directly — this is the ground every terrain,
  water, NPC, and construction feature will stand on.
