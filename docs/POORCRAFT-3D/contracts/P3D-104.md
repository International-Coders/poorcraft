# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-104

- Stage/gate: P3D-100 (world substrate)

## Goal

The generator carries its own evidence: a pure atlas renderer that draws a
seed's biome map (each region colored by biome, shaded by elevation) as an
RGB buffer, cross-seed categorical disagreement checks proving different
seeds produce visibly different worlds, and patch-hash spot-verification
tools — with `poorcraft3d --atlas` writing real PNGs to `poorcraft3d/shots/`.

## Current truth

- `pc3d_world::gen` (P3D-103) produces coherent macro fields, biomes, and
  deterministic patch hashes; 58 pc3d tests green. No rendering or proof
  tooling exists; the original game's N06 seed-atlas pattern (cross-panel
  categorical disagreement) is the model, reimplemented for P3D types.

## Scope

### Must change

- `pc3d_world::proof` (pure, no new deps on the substrate):
  - `biome_color(Biome) -> [u8; 3]` — a fixed, distinct palette.
  - `render_region_atlas(seed, half_regions) -> AtlasImage { size, rgb }`:
    one pixel per region, colored by biome, brightness-graded by elevation
    (peaks lighter, ocean floors darker); deterministic byte-exact output.
  - `cross_seed_disagreement(seed_a, seed_b, half_regions) -> f32`:
    fraction of regions whose BIOME differs between two seeds (the N06
    categorical gate, ported).
  - `verify_patch_hash(seed, coord) -> bool`: regenerate twice, compare
    hashes (cheap spot proof used by tests and the binary).
- Binary: `--atlas <seed> [half_regions]` writes
  `poorcraft3d/shots/atlas_seed<seed>.png` (RGB PNG via the `image` crate,
  added to the APP only — the substrate stays pure) and prints the biome
  census + patch-hash spot checks.
- Makefile: `p3d-atlas` target (`SEED=` parameter, default 1).
- Tests: atlas determinism (byte-identical reruns); palette injectivity;
  cross-seed disagreement ≥ a floor over several seed pairs (worlds differ)
  and 0 for the same seed (a world agrees with itself); atlas symmetry of
  the coordinate span; patch-hash spot checks true for sampled coords.

### Explicit non-goals

- No in-game rendering/window (later stage); the PNG is evidence, not UI.
- No hydrology/site layers on the atlas yet (P3D-301+ extends it).
- No changes to generation itself — this task only EXPOSES it.

## Contracts and invariants

- deterministic behavior: atlas bytes are a pure function of (seed,
  half_regions); identical inputs → identical PNGs.
- authority/ownership: `pc3d_world::proof` owns atlas math; the app only
  encodes/writes PNGs.
- save/load behavior: n/a.
- network behavior: n/a.
- performance budget: an atlas of (2·48+1)² ≈ 9409 regions renders in
  well under a second (debug) — one fbm evaluation per pixel.
- player-visible result: `make p3d-atlas` drops real map images of real
  seeds — the first look at POORCRAFT 3D worlds.

## Verification

- unit/integration tests: determinism, palette injectivity, disagreement
  gate floors, same-seed agreement, hash spot checks.
- persistence/replay tests: n/a.
- visual proof scene: the PNG artifacts themselves; DEVLOG records their
  paths and the disagreement census (human-eye pass over the PNGs).
- smoke or multiplayer test: `make p3d-smoke` stays green.
- profiling/counter evidence: atlas render time recorded in DEVLOG.
