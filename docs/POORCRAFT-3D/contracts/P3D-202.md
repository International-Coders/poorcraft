# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-202
- Title: Base density/material query and the single authoritative final-solid query
- Stage/gate: P3D-200 (hybrid terrain)
- Owner/model: owner directive "FINISH ALL TASKS"; z.ai GLM session
- Date: 2026-09-04

## Goal

One function — `final_solid(gen, wx, wy, wz) -> SolidAnswer { solid,
material }` — answers "what is here?" for every subsystem (mesh, collision,
water, navigation), promoted from the P3D-201 winning heightfield candidate,
and structurally guaranteed to agree with the stored/regenerated patch
cells because both share ONE material-decision function.

## Current truth

- P3D-201's bake-off chose heightfield (98–107 µs extraction, fidelity
  parity). `gen::regenerate_patch` contains the material rules inline
  (surface biome material / Soil / Rock; Water below sea level) — logic
  that must be extracted, not duplicated.

## Scope

### Must change

- Extract `gen::cell_material(surface: Biome, wy: i64, surface_mm: i64)
  -> CellMaterial`; `regenerate_patch` now calls it (behavior identical).
- `pc3d_world::terrain::final_solid(gen, wx, wy, wz) -> SolidAnswer`:
  surface height + region biome → `cell_material`; `solid` = material is
  neither Air nor Water.
- Tests: STRUCTURAL AGREEMENT — for sample patches across seeds and
  signs, every cell of `regenerate_patch` equals `final_solid` at that
  cell's world position (material AND solidity); water semantics
  (below sea level above the floor → Water, not solid); air above the
  surface; spot checks at biome boundaries.

### Explicit non-goals

- No cave/overhang density terms (P3D-203 extends `cell_material`'s
  inputs). No construction overlay (P3D-205). No meshing (renderer stage).

## Contracts and invariants

- deterministic behavior: pure function of (seed, integer coords).
- authority/ownership: `final_solid` is THE world answer; no subsystem
  may reimplement surface logic (guaranteed structurally: the logic lives
  in one function both paths call).
- save/load behavior: agrees with regenerated and stored patches by
  construction (the agreement test is the persistence-shape proof).
- network behavior: n/a.
- performance budget: O(1) query (one surface evaluation + one biome
  lookup); patch-wide agreement test is the throughput witness.
- player-visible result: hills dig exactly as rendered — all consumers
  share one answer.

## Required design check

- Which player story does this improve? Trust: what you see, stand on,
  swim in, and dig are the same world.
- Which two game layers does it connect? Generation ↔ every consumer of
  solidity (the single-answer contract from the blueprint).
- What must a player be able to see or do when it works? Never fall
  through a hill or clip a wall that isn't there.
- What user-approved decision does it depend on? The blueprint's
