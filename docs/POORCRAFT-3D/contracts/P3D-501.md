## Goal

Item authority lives in `pc3d_world::items`: a bounded inventory with
add/remove/split semantics, tools with tiers and durability, harvest
rules gating terrain materials by tool tier, and dig-yields-materials
integration with the edit path — deterministic and UI-independent.

## Scope

### Must change

- `pc3d_world::items`:
  - `ItemId(u16)` and `ITEMS` catalog (code → name, kind, tier).
  - `ItemKind` (Tool { tier }, Material, Food { heal }).
  - `ItemStack { item: ItemId, count: u32 }`, `Inventory` (bounded
    slots): add (stacks then fills, returns leftover), remove, count,
    split.
  - `ToolState { item: ItemId, durability: u32 }` — use decrements,
    breaks at 0.
  - `harvest_yields(material: CellMaterial, tool_tier: Option<u8>) ->
    Vec<(ItemId, u32)>`: Dig yields material-appropriate items gated by
    tier (Rock needs tier ≥ 1, Snow/Sand tier 0 fine).
- Tests: stacking/overflow/leftover; remove semantics; durability break;
  harvest gating (bare hands can't take Rock); yields into inventory.

### Explicit non-goals

- No recipes/crafting (a later task), no UI, no world gen of items.

## Contracts and invariants

- deterministic: pure functions; item codes stable u16s.
- authority/ownership: `pc3d_world::items` is THE item catalog.
- performance: O(slots) inventory ops.
- player-visible: digging gives you things in your pack.
