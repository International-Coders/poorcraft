# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-002
- Title: Versioned world/save/content/protocol headers and refusal behavior for unknown versions
- Stage/gate: P3D-000 (project boundary and truth)
- Owner/model: owner directive "make all in the README"; z.ai GLM session
- Date: 2026-09-03

## Goal

Every POORCRAFT 3D file begins with one fixed-layout header carrying the
format epoch plus independent world/save/content/protocol versions, and the
loader decides — from that header alone, before any parser runs — exactly
whether the file may be opened, with a machine-readable reason when not.

## Current truth

- P3D-001 shipped `pc3d_core::identity`: `P3D_FORMAT_MAGIC` (`PC3D`),
  `P3D_FORMAT_VERSION` (1), and `refuse_foreign_save()` as the outermost
  magic check (`crates/pc3d_core/src/identity.rs`).
- No persisted files exist yet; nothing consumes headers besides the guard
  tests. This task defines the contract P3D-102 (patch store, atomic save)
  will build on.

## Scope

### Must change

- `pc3d_core::header`: fixed little-endian `FormatHeader` — magic (4),
  format epoch (u32), section versions world/save/content/protocol (u16
  each) — with `encode()`/`decode()` (no serde; the byte layout IS the
  contract) and `HEADER_LEN`.
- `SupportedVersions` (epoch 1: world=1, save=1, content=1, protocol=1) and
  `open_decision(bytes, supported) -> OpenDecision`, layered OUTSIDE the
  P3D-001 magic guard: `Accepted`, `TooShort`, `ForeignFormat`,
  `UnknownEpoch(u32)`, `Newer{section, file, supported}`,
  `Older{section, file, supported}` — every refusal carries a human line.
- Policy at epoch 1: any section-version mismatch refuses (no migration
  tooling exists yet); "newer" and "older" are distinguished so the message
  can say upgrade vs downgrade.
- Tests: round-trip, byte-layout stability (exact 18-byte vector), every
  refusal branch per section, foreign magic, truncation, decision
  determinism; the P3D-001 guard remains the outermost check (composition
  test: guard says ForeignFormat before header logic is consulted).
- `poorcraft3d --format` prints the header layout and current supported
  versions.

### Explicit non-goals

- No save/load of real worlds (P3D-102), no content-pack format, no network
  message envelope wiring (protocol version is carried, not used on air yet).
- No migration/upgrade tooling — refusals only, honestly worded.
- No engine/runtime work (P3D-003..005).

## Contracts and invariants

- deterministic behavior: encode/decode are pure, fixed-layout, no env or
  time input; the same header always yields the same 18 bytes.
- authority/ownership: `pc3d_core` owns the header layout; writers and
  readers (future crates) must go through encode/decode, never hand-rolled
  offsets.
- save/load behavior: a file opens only when magic AND epoch AND all four
  section versions match the supported set; otherwise it is refused with a
  reason that names the offending section and both version numbers.
- network behavior: none yet; the protocol version field exists so the
  future envelope can reuse the same refusal matrix.
- performance budget: n/a (single header read per file open).
- player-visible result: `--format` shows the versioned format and the
  rule "unknown versions are refused, never guessed".

## Verification

- unit/integration tests: full branch coverage of `open_decision` per
  section (newer/older/equal), epoch rejection, layout stability against a
  hard-coded byte vector, round-trip, guard layering.
- persistence/replay tests: n/a (P3D-102 wires real files through this).
- visual proof scene: n/a.
- smoke or multiplayer test: `poorcraft3d --format` exits 0.
- profiling/counter evidence: n/a.

## Required design check

- Which player story does this improve? None directly — it protects every
  future story from silent save corruption across versions.
- Which two game layers does it connect? Persistence (future) ↔ everything
  that opens files; the refusal matrix is the format's law.
- What must a player be able to see or do when it works? Never see a
  mystery-crash from an old/newer save — a precise "this file is newer/
  older, update the game" refusal instead.
- What user-approved decision does it depend on? D-002 (brand-new format,
  no silent compatibility) and the roadmap's P3D-002 outcome line.
