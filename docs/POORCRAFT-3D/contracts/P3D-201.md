# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-201
- Title: Prototype and benchmark natural-surface extraction candidates on shared test scenes
- Stage/gate: P3D-200 (hybrid terrain), stage opener
- Owner/model: owner directive "FINISH ALL TASKS"; z.ai GLM session
- Date: 2026-09-04

## Goal

Two surface-extraction candidates are implemented and MEASURED on the same
procedural scenes — smooth hills, highlands, and a coast — across
extraction speed, memory, edit-rebuild cost, and surface fidelity vs the
analytic height function, and the measurements choose the candidate P3D-202
will implement as the authoritative final-solid query.

## Current truth

- P3D-100 stage complete: continuous height function (P3D-103), 16³ patch
  cells of CellMaterial, patch hashes, streaming tiers. 67 pc3d tests
  green at task start.
- The blueprint mandates comparing at least two approaches on shared
  scenes BEFORE choosing (measured, not tutorial preference).

## Scope

### Must change

- `pc3d_world::terrain`:
  - `SolidGrid`: a patch's 16×16×16 occupancy grid — the extraction
    target format both candidates produce.
  - `SceneSpec`: named shared scenes (SmoothHills, Highlands, Coast)
    pinned to (seed, region-center patch, surface-containing y level),
    verified by probe and guarded by tests.
  - Candidate A `heightfield`: solid strictly below the analytic surface
    per column.
  - Candidate B `density_threshold`: 2×2 quarter-meter sub-samples per
    column, solid when a majority of sub-samples lie below the surface —
    the smoothing candidate.
  - `BenchResult` rows + `run_bakeoff()` measuring extract time, grid
    bytes, post-edit rebuild time, and column fidelity vs the analytic
    function (only columns whose surface lies inside the patch window —
    elsewhere all-air/all-solid is correct for both).
- Binary: `--terrain-bench` prints the table.

### AMENDED BY MEASUREMENT (2026-09-04)

- The blueprint's "sharp cliff" scene is ABSENT from the bake-off because
  the pure-heightmap generator produces NO sharp cliffs: a wide sweep
  found no adjacent-region elevation step ≥ 25 m (the 12/6/3 km octave
  cells smooth by construction). Recorded as a real finding — true cliff
  capability arrives with P3D-203's density fields, and the bake-off
  harness will re-measure then. `Highlands` stands in as the
  steep-terrain scene.

### Explicit non-goals

- No true dual contouring / marching cubes mesh GEOMETRY (this bake-off
  measures the solid query a mesher would consume; visual mesh
  comparisons come with the renderer stage).
- No caves/overhangs 3D density fields (P3D-203). No LOD/seams (P3D-206).

## Contracts and invariants

- deterministic behavior: scenes and grids are pure functions of (seed,
  coords); decisions use relative magnitudes, stable across reruns.
- authority/ownership: `pc3d_world::terrain` owns the candidates and the
  bench harness; P3D-202 promotes ONE to the authoritative query.
- save/load behavior: n/a.
- network behavior: n/a.
- performance budget: per-patch extraction far under the 16 ms edit-hitch
  target (measured: ~0.1–0.4 ms release).
- player-visible result: none directly — the decision shapes every
  hillside the player will dig.

## Verification

- unit/integration tests: flat-ground agreement (≤1 cell smoothing
  tolerance), floating-solid guard, grid determinism, bake-off
  completeness/plausibility, scene-pin alignment.
- persistence/replay tests: grid determinism covers it.
- visual proof scene: n/a (P3D-206/207 render terrain).
- smoke or multiplayer test: `make p3d-smoke` stays green.
- profiling/counter evidence: THE deliverable — the measured table
  (DEVLOG), plus a measured-columns column so the fidelity numbers
  cannot be vacuous.

## Done when

Both candidates measured on all three scenes (with column counts), the
decision is recorded with numbers, P3D workspace green, root untouched
and green, docs agree.

## Required design check

- Which player story does this improve? Digging and building: the surface
  answer must be fast, correct, and rebuild locally.
- Which two game layers does it connect? Generation (height function) ↔
  collision/meshing/water (all read the final-solid query).
- What must a player be able to see or do when it works? Hills that match
  the map silhouette and dig without hitches.
- What user-approved decision does it depend on? D-004/D-005 (natural,
  cave-capable, lightweight terrain) and the blueprint's
  measure-before-choosing rule.
