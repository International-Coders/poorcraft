# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-102
- Title: Versioned world header, patch store, atomic save/load, and corrupted-data rejection
- Stage/gate: P3D-100 (world substrate)
- Owner/model: owner directive "FINISH ALL TASKS"; z.ai GLM session
- Date: 2026-09-04

## Goal

Patch files exist on disk under `saves3d/` with the P3D header law enforced
at every open: saves are atomic (temp + rename), patch keys are
deterministic, and a foreign, wrong-version, truncated, or corrupted file
is refused with a precise reason — never guessed at, never partially loaded.

## Current truth

- `pc3d_core` owns the 16-byte header + `open_decision` refusal matrix
  (epoch + world/save/content/protocol, P3D-002) and the identity/save-root
  constants (`saves3d`, magic `PC3D`, P3D-001).
- `pc3d_world` owns the spatial vocabulary (PatchCoord etc., P3D-101).
- No persistence exists yet; nothing writes to disk today.

## Scope

### Must change

- New crate `poorcraft3d/crates/pc3d_save` (deps: pc3d_core, pc3d_world;
  dev-dep tempfile for tests — never touches the original game's
  `worlds/`).
- Framing: every persisted file = 16-byte P3D header | payload length u64
  LE | payload bytes | FNV-1a-64 checksum of the payload. The header's
  `save` section versions the FRAMING; `world` versions world content.
- `paths`: deterministic layout `saves3d/<world>/world.p3d` (header +
  WorldMeta{seed u64 LE, name}) and `saves3d/<world>/patches/p<x>_<y>_<z>.patch`.
- `PatchStore`: `save_patch(dir, coord, payload)` atomic via temp file +
  rename; `load_patch(dir, coord)` -> `Result<Vec<u8>, LoadError>` running
  `open_decision` FIRST, then length and checksum verification.
- `LoadError`: precise variants — `TooShort`, `ForeignFormat`,
  `UnknownEpoch`, `Newer{section}`, `Older{section}`, `LengthMismatch`,
  `ChecksumMismatch`, `Io` — each carrying the numbers (P3D-002's law at
  file granularity).
- `WorldMeta` save/load with the same guard path.
- Tests (tempfile): round-trip; deterministic keys across negative coords;
  foreign magic refused; wrong epoch refused; newer/older save-section
  refused; truncated refused; corrupted payload (bit flip) refused with
  ChecksumMismatch; length mismatch refused; a leftover `.tmp` file never
  affects loads; the store never writes outside its world dir.

### Explicit non-goals

- No patch CONTENT generation (P3D-103) — payloads here are opaque bytes.
- No compression, chunking, or journal compaction (later tasks decide with
  real payload sizes).
- No multiplayer/replication; no migration tooling (refusals only, D-002).

## Contracts and invariants

- deterministic behavior: file names and framing bytes are pure functions
  of (coord, payload); checksum is FNV-1a-64 (house digest).
- authority/ownership: `pc3d_save` owns ALL disk IO for worlds; no other
  crate touches `saves3d/`.
- save/load behavior: atomic rename means a reader never observes a half
  file; every open path goes through `open_decision` before length/sum.
- network behavior: n/a.
- performance budget: one small file per patch; no global scans.
- player-visible result: none yet — but a future corrupt SD card yields a
  precise refusal line, not a mystery crash.

## Verification

- unit/integration tests: the full refusal matrix exercised per branch,
  round-trips, key determinism, atomicity-by-construction, tmp isolation.
- persistence/replay tests: round-trip IS the persistence test here;
  byte-level framing stability pinned by an exact byte vector.
- visual proof scene: n/a.
- smoke or multiplayer test: existing `make p3d-smoke` stays green.
- profiling/counter evidence: n/a.

## Required design check

- Which player story does this improve? "My world survives" — the first
  save is the first promise that building matters.
- Which two game layers does it connect? The header law (pc3d_core) and
  the spatial vocabulary (pc3d_world) become one durable layer.
- What must a player be able to see or do when it works? Save and reload a
  world's patches; a corrupted file says exactly what is wrong.
- What user-approved decision does it depend on? D-002 (new format,
  refusal over guessing) and the save root from D-001/P3D-001.
