## Scope

### Must change

- `pc3d_world::hydro` additions:
  - `Reservoir { region, capacity_kl: i64 (thousand liters, fixed-
    point), volume_kl: i64 }` — capacity derived deterministically from
    the region's terrain basin (v1: slope-scaled by elevation range).
  - `Reservoirs` map: `fill(region, amount) -> spilled u64` (overflow
    passes to the downstream region's reservoir, recursively, bounded by
    chain length), `drain(region, amount) -> u64 taken` (never negative),
    conservation: total volume changes only through fill/drain edges,
    never by arithmetic drift.
- Tests: fill/drain conservation (Σ volumes + Σ spilled == Σ filled
  within a closed system); overflow routes downstream; capacity clamps;
  determinism.

### Explicit non-goals

- No dam-building UI/ops (build ops own the world changes; reservoirs
  model the water side); no evaporation/weather; no simulation loop
  (operations are explicit calls).

## Contracts and invariants

- deterministic behavior: pure integer arithmetic (thousand-liter
  fixed-point); no drift.
- authority/ownership: hydro owns reservoir semantics; save/load via
  pc3d_save framing (snapshot of the map).
- save/load: `hydro/reservoirs.p3d` framed file (round-trip tested).
- network: n/a.
- performance budget: O(chain) for overflow propagation.
- player-visible result: a dam creates a reservoir that HOLDS water and
  fills the river below at spill rate.
