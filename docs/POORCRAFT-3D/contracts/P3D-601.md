## Goal

A settlement has a PLAN: the physical layout of buildings (homes,
workshops, storage, barracks, well, farm), the three anchors
(Bed/Work/Idle per D-033), a road network connecting them, and a service
model that maps buildings to what they provide (food, defense, storage,
comfort). The plan is deterministic per settlement and validated
(buildings must be on walkable terrain, roads must connect, anchors must
be reachable).

## Current truth

- `pc3d_world::settlement` has aggregate scalars (P3D-407). No physical
  plan exists. NPCs (P3D-404) have home/work_site anchors but no
  settlement-level plan binds them together.

## Scope

### Must change

- `pc3d_world::settlement_plan`:
  - `BuildingKind` (Home, Workshop, Storage, Barracks, Well, Farm,
    Watchtower) with per-kind service contributions.
  - `BuildingSlot { kind, cell: CellCoord, size: (u8, u8) }`.
  - `Anchors { bed_cells: Vec<CellCoord>, work_cells: Vec<CellCoord>,
    idle_cells: Vec<CellCoord> }` — the D-033 anchors, derived from
    placed buildings.
  - `SettlementPlan { center: RegionCoord, buildings: Vec<BuildingSlot>,
    roads: Vec<(CellCoord, CellCoord)>, anchors: Anchors }` with:
    - `plan(gen, graph, center) -> SettlementPlan` — deterministic
      layout (center plaza, ring of buildings, roads radiating out).
    - `validate(nav) -> PlanValidation` — all buildings on walkable
      terrain, all anchors reachable from the plaza, roads connected.
    - `services() -> ServiceSummary` (population capacity from homes,
      food from farms, defense from barracks+towers, storage from
      storage buildings).
- Tests: deterministic layout; all buildings walkable; anchors inside
  their buildings; roads connect plaza to each building; service model
  reflects building counts; validation catches bad placements.

### Explicit non-goals

- No 3D building construction (blocks placed in the world — that's the
  P3D-205 overlay); the plan is the DATA model that will drive
  construction. No faction assignments (P3D-605). No per-NPC schedules
  (P3D-404 covers those).

## Contracts and invariants

- deterministic behavior: same seed + center → identical plan.
- authority/ownership: `pc3d_world::settlement_plan` owns the layout;
  buildings are the single source for anchor positions.
- save/load behavior: the plan is derivable from (seed, center) —
  never stored.
- performance budget: plan generation O(buildings × columns).
- player-visible result: (later, rendered) a settlement with a
  recognizable layout — plaza center, buildings around it, roads
  connecting.

## Verification
