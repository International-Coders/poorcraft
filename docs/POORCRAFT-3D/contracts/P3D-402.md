## Goal

Entities exist as registry data: stable unique ids, a spatial index over
patches for near-queries, deterministic update ordering (by id),
persistence through the header law, and per-entity interest state derived
from the P3D-206 LOD selection — the substrate NPCs and creatures land on
in P3D-403+.

## Scope

### Must change

- `pc3d_world::entities`: `EntityId(u64)`, `EntityKind`
  (Villager/Animal/Fish/Marker), `Entity { id, kind, cell, data }`,
  `EntityRegistry` — BTreeMap by id (deterministic iteration),
  `insert/remove/get/update_cell`, `by_patch(patch)`, `entities_near`
  (ascending), `update_order()` (by id), `encode/decode` (fixed-width
  records, deterministic bytes).
- `pc3d_save::entities`: `save_entities/load_entities` through the
  framing law (`entities/registry.p3d`).
- Interest state: `interest_state(registry, viewer) -> Vec<(EntityId,
  LodLevel)>` reusing P3D-206's lod_for (Horizon entities excluded from
  active updates by callers).
- Tests: id uniqueness + deterministic order; spatial exactness
  (by_patch/entities_near incl. negative coords); persistence round-trip
  + foreign refusal; interest states monotonic; encode determinism.

### Explicit non-goals

- No AI/behavior, no rendering, no per-frame physics (movement comes
  with each entity's stage).

## Contracts and invariants

- deterministic: iteration and ordering always by id/position — never a
  hash map order.
- authority/ownership: `pc3d_world::entities` owns entity data;
  `pc3d_save` owns bytes.
- save/load: registry persists as one framed file (bounded scale).
- network: n/a.
- performance: near-queries O(patch bucket); registry O(1) get.
- player-visible: NPCs/animals appear deterministically and persist.
