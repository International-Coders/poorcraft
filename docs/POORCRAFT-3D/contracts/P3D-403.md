# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-403
- Title: Local navigation — patch walkability, bounded A*, portals between patches
- Stage/gate: P3D-400 (movement, entities, NPC foundations)
- Owner/model: owner directive "COMPLETE AT LEAST NEXT 20 steps"; z.ai GLM session
- Date: 2026-09-04

## Goal

NPCs can path: per-patch walkability from the final-solid query, a
bounded A* over patch-local columns (deterministic tie-breaks, hard node
budget), portal links at shared borders where both sides are walkable,
and a two-patch path that crosses through a portal — all deterministic.

## Scope

### Must change

- `pc3d_world::nav`:
  - `NavPatch::from_gen(gen, patch)`: per-column walkable surface
    (surface found near the analytic height ±2 cells; walkable = solid
    floor + 2 passable above), `height(x, z)`, `walkable(x, z)`.
  - `NavPatch::path(from, to) -> Option<Vec<CellCoord>>`: 4-connected
    A* with octile heuristic, closed set as BTreeSet, tie-break by
    (f, then y, then x, then z), hard `MAX_NAV_NODES` budget (None on
    exhaustion), both endpoints must be in-patch and walkable.
  - `portals_to(neighbor) -> Vec<CellCoord>`: shared-border columns
    walkable on BOTH sides.
  - `cross_patch_path(gen, from_patch, from, to_patch, to) ->
    Option<Vec<CellCoord>>`: from-path to the best portal, portal, then
    to-path — deterministic portal choice (first ascending).
- Tests: straight path on flat ground; path routes around a wall
  (built-block wall via edit ops); unreachable returns None within
  budget; portals exist between adjacent walkable patches and are
  on the shared border; cross-patch path is continuous (consecutive
  cells adjacent) and deterministic; every returned cell walkable.

### Explicit non-goals

- No hierarchical multi-patch A* (two-patch chaining only), no roads/
  structure anchors data (anchors land with settlements), no swim
  pathing (water not walkable in v1).

## Contracts and invariants

- deterministic behavior: same patch + endpoints → identical path.
- authority/ownership: `pc3d_world::nav` owns pathing; NPCs call it.
- save/load: n/a (derived from terrain + edits on demand).
- network: n/a.
- performance budget: A* bounded by MAX_NAV_NODES (4096); NavPatch build
  O(256 columns × small vertical scan).
- player-visible result: NPCs walk around obstacles instead of through
  or freezing.
