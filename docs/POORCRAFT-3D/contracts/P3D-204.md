## Goal

Players can dig and fill terrain with bounded brushes; every edit is a
sequenced operation on a per-patch journal; only affected patches are
invalidated; journals persist through the P3D-102 header law and reload
deterministically (regenerated base + replay == the edited world); and a
journal can compact into a patch snapshot that produces identical cells.

## Current truth

- `pc3d_world::gen` regenerates 16³ material patches deterministically and
  exposes `final_solid` (P3D-202/203); `pc3d_save` persists header-framed
  files (patches, world meta) with the refusal law (P3D-102). No editing
  exists yet.

## Scope

### Must change

- `pc3d_world::edit` (pure model):
  - `Brush { center: CellCoord, radius: u32 }` — Chebyshev (cube) brush,
    clamped iteration, `cells() -> impl Iterator<Item = CellCoord>`.
  - `EditOp { id: u64, tick: u64, kind: EditKind (Dig|Fill), brush,
    material: CellMaterial }` with fixed-width `encode/decode` (the
    journal's on-disk op format).
  - `apply_edit(cells: &mut PatchCells, op) -> usize`: Dig turns solid
    cells in the brush to Air; Fill turns Air cells to `op.material`.
    Returns the number of changed cells. Ops outside the patch are no-ops.
  - `affected_patches(op) -> Vec<PatchCoord>`: patch-local invalidation —
    exactly the patches the brush touches.
  - `replay(gen, coord, ops) -> PatchCells`: regenerate the base, apply
    ops in canonical (tick, id) order — deterministic.
  - `compact(ops, base cells) -> Option<Snapshot>`: when a patch carries
    ≥ `COMPACT_THRESHOLD` ops, the journal compacts to a full-cell
    snapshot; `Snapshot::apply` produces identical cells (tested).
- `pc3d_save::journal`: `save_journal/load_journal` and
  `save_snapshot/load_snapshot` for `edits/j<p...>.journal` /
  `s<p...>.snap` files through the header law (refusal matrix applies).
- Tests: brush boundedness + clamping; dig removes only inside the brush
  and only solid cells; fill only fills Air; affected-patch exactness;
  replay determinism (order-independent delivery → canonical result);
  dig-then-verify world answers (final_solid agrees with the edited
  patch's regenerated+journaled state at unedited columns and diverges
  exactly at edited cells); compaction equivalence; journal IO round-trip
  + foreign-file refusal; snapshot byte determinism.

### Explicit non-goals

- No player UI/tool (renderer stage); edits are model-level.
- No erosion/physics, no cave-in, no material conservation accounting.
- No network replication of edits (P3D-802); no construction overlay
  (P3D-205 — edits here reshape NATURAL terrain only).

## Contracts and invariants

- deterministic behavior: replay applies ops in canonical (tick, id)
  order regardless of delivery order; compaction output is byte-equal to
  the replayed result; op encoding is fixed-width little-endian.
- authority/ownership: the edit model lives in `pc3d_world`; disk IO for
  journals/snapshots lives in `pc3d_save` (the only IO crate).
- save/load behavior: per-patch journals under `edits/`; the refusal law
  guards every open; snapshot replaces journal when compaction fires
  (deterministic threshold).
- network behavior: n/a.
- performance budget: apply_edit O(brush cells); replay O(ops × brush);
  compaction O(cells); no global scans.
- player-visible result: dig a crater, reload the world — the crater is
  still there, byte-identically.

## Required design check

- Which player story does this improve? The builder and the digger: "a
  shovel-like tool can alter soil and slopes without a global rebuild"
  (blueprint requirement, now real).
- Which two game layers does it connect? The immutable procedural base
  (layer 1) ↔ persistent natural-terrain edits (layer 2) of the
  blueprint's three-layer terrain.
- What must a player be able to see or do when it works? Dig a crater,
  save, reload — the crater survives byte-identically; neighbors' patches
  never change.
- What user-approved decision does it depend on? D-004 (editable natural
  terrain) and the blueprint's editing requirements (bounded brushes,
  patch-local rebuild).
