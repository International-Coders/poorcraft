# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-506
- Title: Player-diagnosis command — walk the game as a player, render proof PNGs
- Stage/gate: P3D-500 (personal gameplay)
- Owner/model: owner directive "diagnose the game as a player"; z.ai GLM session
- Date: 2026-09-05

## Goal

`poorcraft3d --diagnose <seed>` plays the game end to end as a player:
spawn safely, walk, dig with yields into the inventory, catch and eat a
fish, place a build, cast a learned rune — printing a PASS/FAIL verdict
per system and rendering two proof PNGs (debug overlay + flow map) so a
human can SEE the state. Every verdict is backed by a real assertion.

## Scope

### Must change

- `pc3d_world::diagnose`:
  - `Diagnosis` — ordered check results (name, pass, detail).
  - `run_diagnosis(seed) -> (Diagnosis, Vec<(name, AtlasImage)>)`:
    spawn-safe check, movement check (walk moves the player), dig-check
    (harvest_into stores), fishing check (stock decrements + fish in
    inventory), eat check (hunger clears), build check (Construction
    place + survives terrain dig), magic check (learn + cast), nav
    check (path to a neighbor patch), settlement check (sites exist).
- App: `--diagnose <seed>` runs it, prints the verdict table, renders
  the atlas/overlay/flow-map PNGs, exits 1 if any check fails.
- Tests: diagnosis passes on a good seed; a poisoned check (bad seed
  component) fails; verdict table deterministic.

### Explicit non-goals

- No windowed UI; the diagnosis is the player's proxy until rendering.

## Contracts and invariants

- deterministic: same seed → identical diagnosis bytes.
- ownership: composition only — each check calls an existing tested API.
- performance: full run under 2 s release.
- player-visible: the command output IS the player's diagnostic view.

## Verification

- tests: full-run pass, per-check assertions, determinism.
- smoke: `make p3d-smoke` green.
- human: PNGs committed.

## Done when

Diagnosis green across seeds, PNGs committed, suite green, docs agree.
