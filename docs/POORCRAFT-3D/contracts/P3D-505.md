## Goal

Valve-era engineering components exist on the flow-consumer contract: a
VALVE (on/off gate on a river edge), a PIPE (carries flow potential
between two points without weakening the river), and a WATERWHEEL (reads
flow potential at a site and produces torque proportional to
discharge×slope). All pure, deterministic, D-007-compliant (consumers
never weaken the river).

## Scope

### Must change

- `pc3d_world::engineering`:
  - `Valve { id, on: bool, edge: (from, to) }` — an on-valve passes
    flow; off blocks it. `ValveNetwork` holds valves keyed by edge;
    `flow_through(edge) -> u64` = 0 when any valve on that edge is off.
  - `Pipe { id, from: CellCoord, to: CellCoord }` — carries flow
    potential between endpoints (pure record; no physics yet).
  - `WaterWheel { id, site: RegionCoord, rpm_milli: i64 }` — torque
    derived from discharge×slope at the site (spin rate proportional).
  - `best_wheel_site` integration: site recommendation already exists
    in hydro; engineering wraps it with rpm.
- Tests: valve on/off gates flow; flow_through is 0 with valve off and
  equals discharge with valve on; waterwheel rpm proportional to
  discharge×slope; deterministic.

### Explicit non-goals

- No meshes/rendering (visual network is the proof map), no steam
  physics yet (steam arrives with 702), no multiplayer sync.

## Contracts and invariants

- deterministic: all pure.
- performance: O(valves) per query.
- player-visible: build a wheel on a river, see rpm from real records.
