## Goal

The simulation's deterministic spine exists as pure, dependency-free P3D
code: a fixed-step clock, sequenced command envelopes with total order, an
append-only event journal with a stable digest, per-subsystem deterministic
seed streams derived from one world seed, and a replay-hash harness that
proves identical command streams produce identical results regardless of
render cadence or delivery batching.

  binary. 11 tests green.
- The ORIGINAL game's `lf_game::sim`/`host` proved these contracts work

## Scope

### Must change

- `pc3d_core::clock` — `FixedClock`: integer-microsecond accumulator maps
  real-frame seconds onto whole 60 Hz ticks; `advance(real_dt) -> Range<u64>`
  (inclusive tick numbers; the range API from the start — the count API was
  a proven design trap in the original engine); `MAX_CATCHUP_TICKS = 8`
  deterministic shed.
- `pc3d_core::command` — `CommandSequencer` (restorable high-water mark) and
  `CommandEnvelope<C>` with `canonical_batch` (total (tick, id) order,
  keep-earliest duplicate suppression).
- `pc3d_core::journal` — `JournalEvent { tick, seq, kind, payload: [u64;2] }`,
  append-only `EventJournal` with dense monotone seq and FNV-1a-64
  `digest()` over (tick, seq, kind, payload) in record order.
- `pc3d_core::seed` — `SeedStreams`: derive independent per-subsystem u64
  streams from one world seed via FNV-1a(seed, label); `SplitMix64` RNG with
  `next_u64`, `below(n)`, `unit_f32`; same (seed, labels) → same values
  forever, different labels → independent streams.
- `pc3d_core::replay` — `ReplayDigest` (stable FNV-1a fold helpers for state
  fingerprints) plus the harness tests: a representative command-driven
  sim run under uniform / multi-tick / mixed frame partitions and
  one-by-one vs single-batch delivery must produce identical digests.
- `pub use` of all five modules from the crate root.

### Explicit non-goals

- No world state, no persistence of journal/clock (P3D-102 decides the on-
  disk journal format; P3D-005 gives the harness a runtime).
- No networking, no NPC/terrain logic, no float-heavy math.
- No use of the original game's code by path; contracts only.

## Contracts and invariants

- deterministic behavior: everything is pure integer/FNV logic; f32 enters
  digests only via `to_bits`; same inputs → same outputs, always.
- authority/ownership: `pc3d_core` owns the primitives; future crates
  consume them; no subsystem may keep a second clock or a private journal.
- save/load behavior: sequencer and journal expose high-water marks +
  restore constructors so P3D-102 can persist them; nothing else persists
  yet (explicit).
- network behavior: none; command envelopes anticipate duplicate delivery
  (replayed ids must be inert).
- performance budget: O(n) over pending commands per apply; no allocation
  in the clock path.
- player-visible result: none directly — this is the guarantee that two
  players, two machines, and one replayed stream all see the same world.

## Verification

- persistence/replay tests: the replay harness IS the replay test (on-disk

## Required design check

- Which player story does this improve? Every one — this is the "the world
  is fair and reproducible" guarantee underneath solo and co-op play.
- Which two game layers does it connect? Simulation host (future) ↔
  persistence/replication; the journal is the event spine both will share.
- What must a player be able to see or do when it works? Nothing visible —
  but a replayed stream, a hitch, and a batched delivery all leave the same
  world.
- What user-approved decision does it depend on? D-002 (new format), the
  roadmap's P3D-003 outcome line, and the engine-first sequencing in
  10-BETA-SCOPE-AND-SEQUENCING.md.
