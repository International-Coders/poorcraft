# POORCRAFT 3D Task Contract

## Identity

- Task ID: P3D-404
- Title: NPC identity, roles, needs, schedule, intent, visible activity
- Stage/gate: P3D-400 (movement, entities, NPC foundations)
- Owner/model: owner directive "COMPLETE AT LEAST NEXT 20 steps"; z.ai GLM session
- Date: 2026-09-04

## Goal

NPCs live deterministically on the fixed clock: identity + role, needs
(hunger/energy decay), a day schedule (sleep/work/idle phases by
TimeOfDay ticks), INTENT state machine (Idle/Walking(path)/Working/
Sleeping) that pathes via P3D-403 nav, and a visible activity enum —
the substrate P3D-405+ perception builds on.

## Scope

### Must change

- `pc3d_world::npc`:
  - `Role` (Farmer/Fisher/Builder/Guard) with per-role work activity.
  - `Needs { hunger: u8, energy: u8 }` decaying per tick deterministically
    (hunger up, energy down while working; restored by eating/sleeping).
  - `SchedulePhase` from TimeOfDay ticks (Sleep 0–0.25, Work 0.25–0.7,
    Idle 0.7–0.8, Work 0.8–1.0 — configurable constants).
  - `Intent` (Idle / Walking{path, leg} / Working{site} / Sleeping) and
    `NpcBrain::step(gen, nav, input)` advancing intent: when the phase
    demands work but the NPC is at the wrong place, intent becomes
    Walking a nav path to the work site; arrival switches to Working;
    sleep phase goes home and Sleeping restores energy; hunger rises
    always, eating clears it.
  - `Activity` enum (Idle/Walking/Working{role}/Sleeping/Fishing) for
    rendering + tests.
- Tests: schedule phases flip at the configured ticks; intent follows the
  schedule (walks to work during Work, sleeps during Sleep); needs decay
  deterministically and restore; walking consumes the path leg by leg
  and arrives; determinism (same inputs → same state); a Guard's work
  differs from a Farmer's (activity marker).

### Explicit non-goals

- No perception/memory/karma (P3D-405), no companions (P3D-406), no
  far-settlement aggregates (P3D-407), no rendering.

## Contracts and invariants

- deterministic behavior: needs/intents are pure functions of the input
  history; nav paths already deterministic.
- authority/ownership: `pc3d_world::npc` owns NPC brains.
- save/load: NPC state is plain data (persist with the registry later).
- performance: O(path leg) per tick.
- player-visible: NPCs visibly work, sleep, and walk.
