## Goal

A per-patch debug report and a visual overlay atlas show, for any viewer
position: every patch's LOD level, biome, surface elevation, edit count,
and built-block count — exposed via `poorcraft3d --debug-overlay` so the
streaming/terrain state is inspectable without a renderer.

## Current truth

- P3D-206 shipped LOD selection + seam law. Interest tiers (P3D-105),
  generation (P3D-103), atlas pattern (P3D-104) exist. 97 pc3d tests green.

## Scope

### Must change

- `pc3d_world::debug_overlay`:
  - `PatchDebugRow { coord, lod, biome, elevation_m, edit_count,
    built_count }` (edit_count from journal op count via pc3d_save).
  - `rows_for(gen, viewer, half, journal_counts) -> Vec<PatchDebugRow>`
    over the interest set (ascending).
  - `render_overlay(...) -> AtlasImage`: pixel per region colored by LOD
    ring (distinct ring colors) with elevation shading — rings visibly
    concentric.
- Binary: `--debug-overlay <seed>` writes a PNG + prints the rows table.
- Tests: row completeness/order over the interest set; LOD column in rows
  matches lod_for; overlay determinism; ring colors distinct per level;
  edit counts reflected.

### Explicit non-goals

- No in-game HUD (renderer stage); no mesh-queue visuals (no meshes yet —
  the queue counters exist in P3D-004's profile).

## Contracts and invariants

- deterministic: identical (seed, viewer) → identical rows and atlas bytes.
- ownership: `pc3d_world::debug_overlay` owns the report; the app writes
  PNGs.
- budget: a 33×33-region overlay renders in milliseconds (debug-observed).
- player-visible result: developers (and the owner) can SEE streaming
  state.

## Verification

- tests: completeness/order/LOD agreement/determinism/edit counts.
- smoke: `make p3d-smoke` green; `--debug-overlay` exits 0.

## Done when
